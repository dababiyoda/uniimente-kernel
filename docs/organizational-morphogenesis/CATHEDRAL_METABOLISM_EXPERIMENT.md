## State, authority and recovery protocol

Admission content-binds mission, corpus, source/implementation digests, trigger
and evidence mode. Mission transitions are replayed from EventSpine. Existing
TaskFabric owns task state and receipts; no separate mission database.
One bounded logical worker lease references this ruling; it does not issue a
CapabilityGrant, passport or credential. Logical labels are not authenticated
workload identities. No parent/replacement authority inheritance.

Fixed verifier code in verifier/ independently checks the selected edge and
pin comparison against source data, rather than accepting a worker's success
flag. Worker and coordinator cannot choose, suppress or replace that verifier.
Tests must reject forged output, missing evidence and removed dissent. This
is fixed-code separation, not OS isolation against a privileged hostile host.

Deliberate interruption occurs after durable task submission and before
mission reconciliation. A new process restores exactly the submitted task,
does not rerun it, evaluates it and persists the founder exception. Duplicate
trigger/continue operations are idempotent only for identical content. Stale,
wrong-mission, wrong-state and expanded-scope commands fail closed. A local
single-writer lock prevents concurrent CLI writers; distributed consensus and
disk/power-loss RPO are not claimed. Corrupt/truncated ledgers stop.

Founder surface: status emits one concise result/exception and an exact-state
question. Continue accepts only a manually relayed, content-bound direction
limited to retaining existing pins and closing the audit with the limitation
intact. It cannot update pins, expand budget, issue authority or enable effects.
Chat relay is an operator trust assumption, not cryptographic authentication.
Actual and simulated command modes cannot be mixed. The actual mission stays
AWAITING_FOUNDER unless Alfonso answers its specific exception; test commands
are visibly simulated and cannot count as his answer.
