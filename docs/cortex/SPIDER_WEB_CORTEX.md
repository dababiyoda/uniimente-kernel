## 10. Primary architecture

- **Eligibility:** IntelligenceGenome projection of the Capability Genome; hard gates over provenance-checked
  permission records (law, rights, founder scope, consent, evidence floor, harm, budget, consequence) before ranking.
- **Default routing:** deterministic payload-structure policy; outcome-settled permutation among eligible routes
  only, with a margin and evidence threshold.
- **Proof / truth:** typed proof per epistemic class; formal / empirical / authority split; accountability section
  (strongest counterargument, falsifiers, missing information); model-free verifier that can only lower.
- **Settlement:** competence per method × geometry × conditions × version from verified outcomes only, weighted by
  validation status; predictions and self-assessments refused; rollback.
- **Intelligence conversion:** the routing memory is created by the workflow and changes three decisions: which
  eligible route runs first; which reserved family to build next (frequency of `NO_ELIGIBLE_METHOD` and abstentions
  by geometry); which evaluation items to add (failure families where routes disagree with outcomes). It never
  changes permissions, ceilings or evaluators.

## 11. Strongest counter-position and strongest failure

- **Counter-position (against us):** a strong single model with code execution and tool calls, given the same
  facts, matches the routed seed at lower engineering cost. LLMRouterBench's Best-Single result makes this the
  default expectation.
- **Our counter-position:** jurisdictional refusal, typed falsifiable proof and authority-free receipts are things a
  vendor optimizing for answer volume has reason not to ship; the Kernel, not the vendor, owns authority.
- **Strongest failure:** `GAIN_ABSENT` against the strong baseline. Then the router is retired as a performance claim
  and survives only as a gate-and-receipt layer if it still reduces critical errors.
