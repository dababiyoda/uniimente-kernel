## Increment 4 (same day): #157 worker isolation extracted onto the canonical worker path

### What changed for GREG

- **Workers run in an OS envelope or not at all.** `greg/worker_isolation.py` is extracted from #157 (commit
  `9f5ff18`). Every coding worker gets:
  - a scrubbed environment: only its provider's variables and transport settings, never GREG's keys, cloud
    secrets, `LD_PRELOAD` or `PYTHONPATH`;
  - a private HOME and private temporary directories;
  - a narrow private copy of that provider's credential file only;
  - rlimits, no-new-privileges and death with its parent;
  - bubblewrap user, PID, IPC and UTS namespaces.

  On a host that cannot provide the envelope, `worker.commission` refuses before dispatch, and no spend occurs.
  Provider network access remains, and is reported as such; this is not a network-isolation claim.
- **Worker-written acceptance tests are untrusted code.** They now run in bubblewrap with no network, no
  credentials and no view of the body. Without the envelope they are refused and recorded as failed; they never
  run with GREG's own reach. Previously they ran with network denied but with full filesystem access.
- **GREG's git no longer executes what a worker planted.** Trusted `.git` metadata is copied out before the worker
  runs and restored before GREG's collection touches the clone. GREG's git also runs with
  `core.hooksPath=/dev/null`, `core.fsmonitor=false` and no global configuration.
  - **Measured on the branch before this increment:** an executable `post-commit` hook planted by a worker ran
    inside GREG's collection process, and a planted `.git/config` filter survived into the collected clone.
  - **After:** neither occurs (`test_an_executable_hook_planted_by_the_worker_never_runs_in_gregs_collection`, and
    #157's `test_parent_collection_restores_trusted_git_metadata_before_filters_or_hooks_can_run`).
- **Bounded, cancellable supervision.** Worker output is file-backed and capped at 1 MiB per stream. STOP terminates
  the worker's whole process namespace.
- **An interrupted worker is reconciled.** The action becomes UNCERTAIN with the signed cap reserved, its receipt is
  kept, and it is never blindly retried; the founder reconciles it. This was ported into `greg/missions.py` beside
  the existing metered-spend booking, which stays canonical.
- **Collector refusals instead of exceptions.** These now FAIL the collection, and the appraisal rejects any
  collection that did not complete:
  - over-cap or invalid spend;
  - an oversized diff;
  - a deliverable outside the workspace.
- **Document orders can require a verbatim quote** of the frozen source context, checked byte for byte by the
  appraisal.
- **The doctor reports whether this host can confine workers,** with the fix. It is never a body prerequisite. The
  Chromebook runbook gains an optional `sudo apt install -y bubblewrap`.

## Increment 5 (same day): the console signs only for its owner

### The hole, measured before the fix

Any process that could reach `127.0.0.1:8766` could take over the founder's console. It read Mission Control, took

- **All links, forms and redirects are rewritten under the owner path.**
- **Owned public pages (`/owned`) stay public,** and are served under a sandboxing content policy.
- **Commands still need the founder's Ed25519 signature and the body's Gate.** The session only decides who may
  ask this console to sign.

### Evidence

  nothing is signed, and even a correct CSRF token is refused.
- `test_the_private_link_works_once_and_the_session_cookie_is_narrow` checks four things:
  - the link is spent after one use;
  - a forged cookie is refused;

  sells unlicensed content, nothing is listed or sold, the mission never closes, and the founder is asked once.
- **Limits.** This screens declarations and wording. It does not prove title, and wording can evade a pattern
  screen. A false positive is possible: a guide about emergencies would be refused for the word "emergency". The
  refusal names the matched phrase so the founder can reword. Commerce is FIXTURE only; no money moves.

### A local gain that damages the whole

- **The hole.** The engine judged each strategy only by the checks it declares it advances. On a signed mission, one
  strategy raised throughput by breaking safety, which had passed, and another restored safety by breaking
  throughput. The body alternated them on every tick: 14 real writes in 14 ticks, indefinitely. It never tried the
  strategy that satisfied both, and never asked. The existing decoupling warning could not see it, because every
  action reported DONE.

  and that the action does not advance, is watched. If its next real measurement fails, the action is blamed

- **Outcome.** With a route that keeps both checks, GREG takes it after two writes and closes. Without one, it asks

  carries `tradeoffs`. Writing stops, and the plant is left as GREG found it, safe.
- **Limits.** Blame is by sequence, not proven causation. World drift between an action and the next observation is
  blamed on the action, which errs toward not repeating it. Only the next observation of each check counts.

## Increment 8 (same day): the browser and coding workers behind the #26 relay

### The mechanism

`run_confined`'s seccomp filter denies every socket call. A browser or a provider client cannot run under it.
`foundry/systems/relay_door.py` gives them the same single way out without the filter:

- **Namespace.** The program runs in a bubblewrap network namespace (`--unshare-net`, no privilege). Only its own
  loopback exists. The body's loopback and every outside address are unreachable directly.
- **Door.** Inside the namespace, before the program starts, a small front listens on that loopback as an HTTP
  proxy (CONNECT for TLS, absolute-form requests for plain-http loopback pages). Each request becomes one
  `CONNECT <host> <port>` line on an inherited control socket.
- **Relay.** The body's relay decides each request against the identity's exact allowlist and journals it in the
  hash chain. It opens the upstream, through the mandated proxy where there is one, and passes back a data socket.
- **Program.** The program starts with `HTTPS_PROXY`/`HTTP_PROXY` naming the door. A program that ignores those
  settings simply has no network.

This was prototyped first, outside the repository. An inherited socket survives bubblewrap, loopback is up in the
new namespace, and the outside is unreachable.

### On the mission path (a body initialised with `--confined-egress`)

- **`browser.render`.** It runs Chromium behind the door. A per-call relay is allowlisted for the signed target
  alone and shares the body relay's journal and mandated proxy. On a signed mission the page's JavaScript runs, its
  beacons (by name and by IP literal) are DENIED and journaled, and nothing reaches them. The journal also shows
  Chromium's own background calls to Google hosts, DENIED. In the unconfined route those went silently to a dead
  proxy.
- **Coding workers.** They keep their provider authentication but run behind the door as identity
  `worker.commission`, allowlisted for the provider endpoint declared in the capability manifest. On a signed
  code-change mission the provider call succeeds and is journaled. An undeclared host is refused with 403, the
  body's loopback is unreachable directly, and the work is collected and accepted as before. The isolation evidence
  reads `relay-door: worker.commission`. Acceptance tests still run with no network at all.
- **Both new mission tests fail on the old code.**

### Negative evidence

- **The first browser run failed.** `--host-resolver-rules=MAP * ~NOTFOUND` also mapped the door's own
  `127.0.0.1`, so Chromium never reached it and rendered `ERR_PROXY_CONNECTION_FAILED`. A direct adapter call had
  hidden this, because I checked only the route string and not the page text. The rule now exempts the namespace
  loopback, where nothing but the door exists.
- **Chromium runs without its own sandbox here.** It cannot nest its user namespace inside GREG's, and as root it
  cannot sandbox at all. The receipt reports `os_sandboxed: false`. The namespace and the read-only root are GREG's
  containment.

## Increment 10 (same day): `browser.session` behind the #26 relay, and two leaks found on the way

### Negative evidence, measured before the change

Unconfined `browser.session` claimed that "every other request is aborted and counted". A probe on this branch at
`28c3e9c` showed that was false in two ways:

- **WebSockets bypassed the allowlist.** Playwright's `context.route` never sees a WebSocket. A page signed for
  `127.0.0.1` opened one to `127.0.0.2`, which was not on the list. The bytes arrived, and nothing was counted.
- **The allowlist compared host names only.** A page on a loopback target reached another port on `127.0.0.1` by
  `fetch` and by WebSocket. On a real body that means the Console, the model server or any other local service.

### What changed for GREG

- **In the browser.** The allowlist is now exact origins (host and port), taken from the signed params:
  - the start URL;
  - absolute `goto` URLs on the signed hosts;
  - `also_hosts` (`host` means port 443; `host:port` means that port).

  WebSockets are routed too. One outside those origins is never connected and is counted in `blocked_websockets`.
  Refusal means not connecting: a synchronous `close()` inside Playwright's WebSocket handler never returns,
  because the handler runs on Playwright's own event loop. That hang was hit and diagnosed here.
- **On a body with `--confined-egress`.** `browser.session` is in `CONFINED_EGRESS`. Its Chromium runs in a bubblewrap
  network namespace whose only way out is the relay door, allowlisted for exactly those origins. Every connection is
  decided and journaled at the relay, WebSockets included. Two adaptations were needed:
  - Playwright's driver, not the body, starts Chromium, so no descriptor of the body's survives that route. The
    door therefore reaches the relay over a one-time Unix socket in the session's private (0700) directory. The
    body accepts one connection, from its own user only, then removes the path.
  - The door keeps Playwright's pipe (descriptors 3 and 4) for Chromium and closes everything else of the
    launcher's.
- **Downloads still work.** They land in the session's directory through the namespace.
- **Fail closed.** Without bubblewrap network namespaces, nothing is launched.

### Evidence

- `tests/integration/test_greg_confined_egress.py::test_a_browser_session_drives_pages_behind_the_relay_and_nothing_else_leaves`,

  - **`kept`.** A signed mission drives two pages and downloads a file. The page's WebSocket, `fetch` by IP and

  - **`removed`.** Playwright's `route` and `route_web_socket` are patched out, as if a bypass or regression removed

  - a door on a path serves a program another launcher started;

### Five roles and two passes for increments 4–6 (authority boundaries changed)

**Builder.** Every change closes a hole that was reproduced on this branch first: the console signing for any local
process, worker-planted hooks running in GREG, unconfined acceptance code, a NaN budget admitting any spend, and
GitHub reads from the body process. Each fix reuses an existing mechanism (#157's modules, the #26 relay, the

  supervisor that captures stdout to a log, any unconfined process of the same user could read the log and spend

**Operator.**
- bubblewrap becomes a dependency for coding workers only, and the doctor reports it.
- GitHub's Ubuntu runners have not yet been shown to allow bubblewrap's user namespaces.
- Restarting the console invalidates the old session, so the founder opens a new link.

**Beneficiary representative.**
- **Added friction:** one link per console start.
- **Gained:** no program on the machine can obtain the founder's signature through the console.
- The phone channel is unchanged.

**Constitutional reviewer.**
- No authority is added. The session only decides who may ask the console to sign; every command still carries
  the founder's Ed25519 signature and passes the body and Gate.
- Paid approvals became narrower, bound to the spend state.
- Nothing was merged, published or spent.

**Pass 1 (structural inversion).**
- Owner authentication turns the console from "reachable means trusted" into "possessing the founder's private
