The execution module only consumes pre-existing registered authority.

## Pass 1

- Founder-Intent Steward: preserve offline pursuit and the full computer-use,
  capability-growth and business/team horizon. Prove one small actual task now.
- Systems Architect: static DurableWorkflow is already canonical. A bounded host
  may wake/restart it; workflow checkpoints and events remain the only mission
  state. Do not generalize the synthetic Goal Chase schema just for this task.
- Adversarial Reviewer: a worker exit/signature/report is not closure. Re-read
  source blobs in a separate appraiser, compare retained bytes and derive the
  result. Missing authority must prevent the tool from running.
- Operator/Maintainer: cap duration, restarts, subprocess time and source sizes;
  sleep while waiting and stop children when the host exits. No service install.
- Evidence/Welfare Guardian: test credentials do not authenticate Alfonso.
  Preserve failed checks and distinguish local data, test control, hardware
  operation and commercial outcomes.

Alternatives: no action leaves the gap; a manual audit is cheaper but proves no
persistence; adapting #97 into a general real-work runtime expands contracts
prematurely; a full broker/framework/organization adds unnecessary ownership.
The reversible fixed-workflow experiment wins for this bounded question.

Disadvantages D1: parent-host failure still needs an independently managed host
restart and pre-existing authority provider. D2: trusted-host process isolation
does not contain arbitrary hostile native code. D3: cached repository snapshots
can be stale. D4: finite audit competence is not capability growth.

negative control must never run its executor without approval.

not the completed founder-authenticated hardware mission. Single-author role
