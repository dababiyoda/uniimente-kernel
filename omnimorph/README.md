# OMNIMORPH

## Purpose

Compose temporary institutional organs from a passed Advantage Architecture, a
dependency-aware Composition Plan and registered Capability Genomes. OMNIMORPH
simulates the proposed organ, records separate human ratification, accepts an
exact canonical Gate activation receipt and supports evidence-backed retirement.

OMNIMORPH does not execute an organ, create a legal entity, mint credentials,
move money, grant authority or activate itself.

## Institutional Morphogenesis compiler — Phase 3

`OrganizationCompiler` extends OMNIMORPH's design role. Given a valid bounded
MissionContract, it deterministically emits materially different
OrchestrationGenome hypotheses and a transparent TopologyDecision. It preserves
the static DurableWorkflow and do-not-instantiate choices, lets static win exact
ties, defers evidence-gated forms and refuses all execution admission.

Each v1.1 genome contains one content-bound, `DESIGN_ONLY` zero-trust profile.
The profile recombines content-addressing, transparency receipts, per-transition
verification, fresh one-task workload capability, independent appraisal,
thresholded improvement proposals and static fallback. It references the
existing Event Spine, identity, authority, provenance and Gate owners. It does
not deploy a blockchain, token, second ledger, second identity system, second
policy engine or second consequence path.

The compiler imports no runtime, model, network, Event Spine, identity issuer,
authority engine, Gate, scheduler or worker executor. Its ranking is a
`HYPOTHESIS_ONLY` experiment input—not organizational knowledge, ratification or
proof that a topology works.

## Buildability contract

- **Existing mechanism:** Advantage Foundry, Spider-Web Tribunal, 55-technology
  Composition Plan, Capability Genome Registry, Evidence Ledger, human
  ratification and canonical Consequence Gate receipts.
- **Defined interfaces:** `OmnimorphEngine.compose`, `simulate`,
  `propose_activation`, `record_gate_activation`, `retire`, and the inert
  `OrganizationCompiler.compile` design interface.
- **Bounded authority:** the engine outputs `PROPOSED_NOT_EXECUTED`; the compiler
  outputs `REFUSED_PENDING_SEPARATE_PHASE_DECISION`. Neither may authorize.
- **Available dependencies:** registered genomes, passed tribunal report, valid
  Composition Plan, legal operator, immutable MissionContract, pinned RFC-8785
  canonicalizer, resource ceilings and kill conditions.
- **Security model:** deny by default; exact content binding; minimum capability;
  short-lived identity/lease; freshness; independent evaluation; static/refusal
  fallback; reconciliation before uncertain-effect retry.
- **Security gaps:** production key custody, actual network enforcement,
  distributed revocation, hardware attestation and external anti-equivocation
  witness remain unavailable or not implemented.
- **Recovery:** preserve evidence, refuse or suspend admission, revert the scoped
  design slice and retain static DurableWorkflow.
- **Legal operator:** a named human or lawful entity; never UNIIMENTE,
  OMNIMORPH, Foundry or a child organ.
- **Replaceable:** models, providers, runtimes, storage, canonicalization
  implementation and candidate forms may change behind versioned contracts only
  through a new linked decision.
