## Independently enforced offline boundary

The launcher installs an unprivileged Linux seccomp filter before any application import. It clears the inherited environment, passes only explicit paths and synthetic fixture inputs, closes inherited descriptors above stderr, disables core dumps and applies a CPU ceiling. Socket creation, connect/bind/listen/accept, io_uring, namespace entry and process-injection/foreign-descriptor mechanisms are denied. Anonymous local Unix socketpairs remain available for asyncio. The filter follows fork/exec. Each launch first executes a separate native-libc probe: IPv4, IPv6 and Unix stream/datagram socket creation all return EPERM; anonymous fixture socketpair communication passes. No Twitter or other service is contacted by this probe.

This is OS network containment, not application mocking. Test subprocesses and dependencies inherit it. There are no production credential values in the test environment or checked-out credential files; fixtures use explicit synthetic keys. It is **not an arbitrary-code filesystem sandbox** and is not claimed to resist a privileged same-host adversary. Only reviewed project code was exercised. Linux documents filter inheritance and the limits of [no_new_privs](https://docs.kernel.org/6.18/userspace-api/no_new_privs.html) and [seccomp](https://docs.kernel.org/7.1/userspace-api/seccomp_filter.html).

The earlier api.twitter.com path was not rerun unchanged. User/network namespace probes failed with EPERM; Landlock was unavailable. The materially different seccomp boundary was installed and verified before broad execution. Docker/Podman are absent. Because this boundary also forbids TCP loopback, `test_exact_packaged_command_protected_bridge` and `test_real_producer_consumer_restart_and_negative_controls` fail visibly on socket creation. To rerun them here requires a facility with an independently enforced network namespace/container that permits only the needed local fixture connection, has no external interface or production credentials, and encloses every subprocess. No proxy, alternate hostname or suppressed check is used.

The installed ASGI fixture exercises actual producer serialization, HMAC, consumer JWT/HMAC admission, schema validation, evaluator, SQLite and canonical durable ledgers. It imports the consumer from Docker's COPY composition and the producer from its reviewed source. It verifies both import the installed Kernel distribution. It replaces only urllib's HTTP carrier with the real ASGI application's TestClient; it does not override routes, authentication, evaluation or persistence. It is not the exact Uvicorn CMD or an image-build proof. DALEOBANKS is exercised from its reviewed source checkout; no DALEOBANKS application wheel/image build is claimed. Both sides load the installed shared Kernel wheel. Existing exact-CMD tests and older CI/subprocess evidence remain separate gates.
