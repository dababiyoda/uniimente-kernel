## Demonstrated defect → minimum repair

The protected counterexample is `PHASE4_RECONCILIATION_BLOCKER.md` and
`phase4/evidence/evaluator-boundary-negative.txt`: nonexistent evidence with a
different identity and caller acceptance reached VERIFIED in the remote line.

The repaired seam rejects every non-null legacy `accepted` argument.
A verifier string cannot select code or provide a decision. A fixed child
process under verifier/ receives copied retained bytes, rederives the declared
route independently of Linker, and produces an appraisal. Its output includes
the report, frozen policy/code/schema hashes and mission/task/submission/source/
result/worker/lease bindings. It cannot invoke tools, network, subprocesses or
write files through its guarded Python paths. No worker callback is accepted.

The resolver checks the existing ledger chain, unique canonical records,
digests, causal parents, frozen source snapshot and evaluator policy. Source or
result ambiguity cannot silently choose a preferred version. A durable START
record precedes invocation. A completed appraisal is reused without rerunning;
START without completion refuses and requires reconciliation. The reducer's
VERIFIED/CLOSED guard resolves a completed appraisal instead of creating one.
Caller identity and receipt references alone cannot bypass that guard.

Missing/poisoned evidence and disagreement quarantine an otherwise intact
submitted task and retain an exception. Corrupt ledger chains are refused
without appending onto invalid history; recovery must reconcile the preserved
chain before transitions resume. Required evaluator dissent survives appraisal
and simulated closure. Open exceptions block dissolution even when omitted by
the caller. Finalization cannot use a fabricated evidence reference.

## Threat boundary and protected dissent

Evidence tier: local executed simulation tests, not hostile-host assurance.
Worker output and coordinator requests are untrusted inputs; verifier code,
canonical EventSpine writer and the host running them are trusted infrastructure.
The fixed read-only child is a separate execution compartment, but its Python
audit hook is NOT an OS sandbox against malicious native code or a privileged
parent. A host/root attacker can replace code or fabricate the entire store.
This is explicitly not remote attestation or cryptographic appraisal provenance.

The CMC writer lock rejects stale/concurrent appraisal writers, and durable
markers are fsynced. It does not retrofit distributed consensus or transactional
multi-writer guarantees into every historical EventSpine caller. Those remain
outside this single-writer experiment. Power-loss/RPO guarantees remain UNKNOWN.

The fixed appraiser only evaluates the pre-registered manifest-route question.
It does not verify live organ execution, current-main interoperability, real
mission quality or economic acceptance. An older manifest pin may be intentional;
both that dissent and the no-live-interoperability limitation are retained.
