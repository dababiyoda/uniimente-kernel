## 2. The mechanism: v3's, with one change, the key

**Key.** `condition_competence.KEY = "dimension_objective"`. A request's cell is (geometry, dimension band, declared objective name). Both parts are read from the request alone (`len(shift)` and `function`), and nothing measured on any holdout enters it.

**Unchanged from v3:**
- **Shadows:**
  - an inert shadow of the founder-attached admitted `blackbox_multistart_lbfgsb`, triggered by a settled `VERIFIED_UNMET` of the incumbent in the same cell from another problem;
  - at most 36 per cell, and none once the cell has fired;
  - each at the request's own budget, checked by the genome's own verifier;
  - re-observations reuse the seeded shadow, and every trial's cost is counted from the compile receipts.
- **Preference:** the paired sign test per cell fires at p < 0.05 with at least 5 discordant pairs.
- **Routing basis:** the alternative is routed only in a fired cell, through the exact adapter. The basis reads "live paired evidence, outside the admitted envelope (2-10 d), not a re-admission".
- **Untouched:** the admission index, `_settled_inhibition` and `_settled_preference`.

**Production stays on v3's key.** `KEY` keeps v3's default (`"dimension"`) in production. Only this harness sets the finer key, so a v3b GAIN supports adopting it but does not adopt it.

## 3. Arms (holdout: 200 instances; same evaluator and τ in every arm)

| Arm | Journal | Mechanism |
|---|---|---|
| PRE | none | on, v3b key |
| LEARN | the 120-mission stress body | on, v3b key |
| CONTROL | same stressed journal | off |
| A, coarse key | same stressed journal | on, v3's dimension-only key, which reads the same pairs merged across objectives |
| S, shuffled objective | same stressed journal | on, v3b key. When the evidence is read, each stress pair's objective label is reassigned among the five by a seeded fair coin (seed `antifragility-v3-shuffle`) |
| B1, compute-matched | none | off. Each HIGH instance runs the incumbent k times, at seed + 100000·j and at its own accepted budget, and keeps the best answer. k = ⌈(LEARN's HIGH holdout evaluations, shadows included, + all stress shadow evaluations) / (50 × the HIGH budget)⌉. **This replaces v3's B1**, in which the raised budget exceeded the swarm's compute limit and the swarm abstained on every instance. Each run here stays within the accepted budget. |
| B2, best-of-both | none | off. Both methods on every instance, the better verified answer kept. A 2× reference, not a kill rule |

The arms run in this order: PRE, LEARN, CONTROL, A, S, B1, B2. Holdout instances are compiled directly, so they never settle.

## 4. Verdict rule (fixed here), in order

1. **REGRESSION** if LEARN passes fewer LOW holdout instances than PRE (the LOW floor is 0), or fewer in total than CONTROL.
2. **NO_GAIN** if no cell preference fired during the 120 stress missions, or if LEARN's total is not above both PRE and CONTROL.
3. **NO_GAIN (compute-attributed)** if LEARN's total is not above B1.
4. **NO_GAIN (condition not causal)** if LEARN's total is not above S.
5. **GAIN** if LEARN is above PRE, CONTROL, B1 and S, no stratum × objective cell passes fewer instances under LEARN than under PRE, and the one-sided exact sign test of LEARN vs CONTROL on discordant holdout pairs gives p < 0.05.
6. **INCONCLUSIVE** if the counts satisfy 5 but the sign test does not.
7. **NO_GAIN** otherwise: the totals pass rules 2-4, but some cell regresses.

A against LEARN is reported, not ruled. If A is at or above LEARN, the finer key adds nothing over v3's key on this data. Stress damage, shadow cost, recovery cost (the mission at which each cell fired) and latency are reported with every verdict.

## 5. Power, computed before the freeze (`power.py`, its output in `power.txt`)

**Method.**
- Per-mission discordant rates per HIGH objective come from v3's stress pairs, Laplace-smoothed. These are hypothesis-generating data, used here only for the design.
- The holdout is simulated from the same rates.
- The rule is the one above, including "a fired cell where the alternative loses more than it wins counts as a regression".

**Simulated outcomes:**

| Stress per objective | Holdout per cell | P(GAIN-shaped holdout) |
|---|---|---|
| 24 | 10 | 0.72 |
| 40 | 10 | 0.76 |
| **24** | **20** | **0.935** |

So the owner's gate (power ≥ 0.8) is met by enlarging the holdout to 20 per cell, with 24 stress missions per objective. Under that design, the probability that the preference fires is 0.98 for Rosenbrock, 0.66 for Griewank, 0.15 for Sphere, 0.02 for Rastrigin and about 0 for Ackley.

**Limits of this estimate:**
- the rates come from 6-7 pairs per objective;
- the simulation treats pairs as independent;
- it assumes the first stress mission per objective only triggers shadowing, whereas in the run shadowing begins at the first failure from another problem in the cell.
