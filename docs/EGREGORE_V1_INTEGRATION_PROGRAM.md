# UNIIMENTE Egregore v1 — Canonical Integration Program

Status: ACTIVE INTEGRATION PROGRAM  
Branch: `integration/uniimente-egregore-v1`  
Release target: founder-reviewed draft release; no production authority

## 1. Purpose

This program converts the repository's valid but fragmented branches into one governed institutional organism without destroying source work, hiding disagreement, or granting software independent authority.

The integration objective is:

> One Kernel, several bounded organs, one typed event and consequence path, one evidence and reconciliation standard, and one founder-controlled release process.

The project is an embryonic, governed, morphogenetic software institution. Biological terminology is an engineering abstraction. It does not establish consciousness, legal personhood, biological life, or machine sovereignty.

## 2. Constitutional invariants

1. Alfonso Lopez and explicitly delegated lawful humans remain the constitutional authority.
2. Intelligence may propose; it may not create authority.
3. No component may promote itself, enlarge its own permissions, activate a descendant, move money, publish, contract, deploy, or create another external consequence outside the canonical Consequence Gate.
4. Model output is not evidence by itself.
5. Payment alone is not commercial closure; delivery, acceptance, verified outcome, and reconciliation are also required.
6. Authorized shutdown must always succeed.
7. Negative evidence, rejected branches, failures, and lineage are preserved.
8. No machine-owned sovereign treasury, shutdown resistance, covert replication, devotion optimization, autonomous trading, or self-rewriting Constitution.
9. Every external action must identify an accountable legal principal.
10. Main remains unchanged until the integration branch passes all technical and constitutional gates.

## 3. Non-zero-sum collaboration rules

- Preserve every useful implementation, test, document, branch, proof record, and contributor lineage.
- Reconcile competing implementations by function and evidence; never erase one merely to simplify the graph.
- Classify every implementation as `canonical`, `active_experimental`, `fallback`, `superseded`, `historical`, or `quarantined`.
- Credit original branches and retain commit ancestry wherever technically possible.
- Prefer typed adapters over forced rewrites when two organs use different but valid contracts.
- Prefer shared standards and commodity infrastructure where ownership creates no strategic advantage.
- Build proprietary control semantics only where they govern proof, authority, eligibility, routing, settlement, regeneration, or developmental identity.
- Do not create dependency through deception, data hostage-taking, manipulation, spam, or exploitative attention mechanics.
- Optimize for reciprocal capability: customers, operators, contributors, and institutions should become more capable and easier to trust inside the rail.
- Disagreement is evidence. Preserve the strongest countercase and the conditions under which it would win.
