# Project Cognition Continuity Addendum

This addendum extends `docs/PROJECT_COGNITION_SOP.md`.

## Continuous ingestion

The Project Source Census is a snapshot, not a finish line. At each major build cycle, an agent with Project-source access must enumerate currently visible Project-backed sources, compare them with the census, add new sources or a dated successor census, identify new founder corrections and implementation claims, and state what remained inaccessible.

A source is institutionally ingested only when it is discoverable from repository cognition surfaces and its durable implications are routed to the appropriate owner. A model having once read a source in chat is not sufficient.

## Source-to-code trace

For material capabilities preserve:

`founder source -> intended effect -> decision -> implementation -> verification -> runtime capability -> outcome -> retained learning`.

A partial implementation must preserve the residual aspiration instead of silently shrinking it.

## Agent context checksum

Before a material architecture decision, the worker must be able to answer the applicable questions:

- Who is root authority?
- What is GREG?
- What is the current bottleneck?
- What is functional morphogenesis?
- What is Capability Genesis?
- What is the acquire-before-invent ladder?
- What role does Build-Your-Own-X play?
- What counts and does not count as VEPMC?
- What is the developmental authority ceiling?
- Who owns shared authority/evidence truth?
- Which repositories are organs, substrates, or capability candidates?
- Which source families were searched?
- What context was unavailable?

Failure to answer means context reconstruction is incomplete.

## Communication matrix

- Founder Intent Ledger: durable intent and lineage.
- Intent record plus verbatim source: controlling correction.
- Project Source Census: source discoverability.
- Project Cognition SOP and this addendum: reconstruction/propagation procedure.
- AGENTS.md: universal agent entry.
- CLAUDE.md: Claude entry.
- Copilot instructions: Copilot entry.
- README: human/agent project entry.
- Recursive Collaboration Protocol: constitutional convergence.
- Coordination issue: cross-agent/cross-repo handoff.
- Active product PR: implementation-local evidence and steering.
- PR/issue templates: required context fields for future work.
- Organ-local cognition file or issue: repository role and canonical links.
- Tests/verifiers: executable claims, never prose authority.
- Archived experiments: evidence/mechanism substrate, never current product truth.

Write durable truth once canonically and reference it elsewhere to reduce drift.

## Propagation receipt

For every material cross-project correction record:

- canonical source;
- affected repositories;
- surfaces attempted;
- surfaces successfully updated;
- blocked/unavailable surfaces;
- follow-up owner;
- whether contracts changed;
- whether runtime integration exists.

Never claim "propagated everywhere" without a receipt.

## Anti-context-loss test

A competent new coding agent entering through a normal repository instruction surface should be able to discover, within a bounded path:

1. that the repository participates in UNIIMENTE;
2. canonical founder intent;
3. source census;
4. cognition SOP;
5. repository role;
6. current bottleneck;
7. coordination surface;
8. authority ceiling;
9. handoff procedure.

If not, propagation for that repository is incomplete.
