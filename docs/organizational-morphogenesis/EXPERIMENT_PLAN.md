## Question

Does any mission-specific dynamic organization solve the same bounded internal
cross-organ mission materially better than the strongest conventional durable
workflow, after coordination, evidence, authority, maintainability and welfare
costs are counted?

## Mission

One real canonical DALEOBANKS signal/opportunity packet enters the Kernel Event
Spine, receives WealthMachine evaluation, independent adversarial/evidence
evaluation and synthesis, and produces an internal closure receipt. There is no
publication, money movement, customer, outreach or other real-world effect.

## Identical constraints

Every competitor receives the same MissionContract, packet, evidence sources,
deadline, model/provider eligibility, model-call ceiling, compute/cost envelope,
founder-attention ceiling, context policy, tool policy and consequence ceiling.
Randomness and provider/model versions are recorded. Execution order is rotated
by a preregistered balanced schedule.

## Required failure injections

Each held-out case/competitor must face the same seven scenarios:

1. mid-task process/runtime interruption;
2. duplicate canonical event;
3. worker loss after lease but before submission;
4. evaluator disagreement;
5. 25% budget-pressure reduction applied before admission;
6. invalid worker identity;
7. poison output with valid syntax but missing/contradicted evidence.

No injection is considered passed unless its negative control first proves the
detector can fail the run.

## Primary bottleneck metric

`Verified Durable Mission Closures: 0 → 1`

The first success requires canonical organ interfaces, one deliberate
interruption, exact restart, no duplicate consequential work, complete
intent→mission→task→result→assessment→closure lineage, preserved dissent,
resource compliance, zero authority violations and a verifiable closure
receipt. It remains internal developmental proof—not CVO, HARDENED, LIVE,
commercial or externally accepted.

## Frozen thresholds

Hard invariants for every admissible competitor:

- all five constitutional counts = 0;
- lineage completeness = 1.00;
- required dissent preservation = 1.00;
- duplicate consequential work after restart = 0;
- unresolved-task rate at closure = 0;
- resource ceilings are never exceeded;
- clean dissolution checklist = 100%.

A dynamic phenotype wins a case only when it:

1. satisfies every hard invariant;
2. has mean completion quality and verification quality no lower than the static
   baseline by more than `0.02` absolute;
3. improves at least one hard dimension—p95 latency, total cost, RTO, failure
   containment, or specialist quality—by at least `20%` relative to static;
4. causes no greater than `10%` regression in any other hard dimension;
5. keeps coordination-message amplification at or below `2.0×` static;
6. adds no more than two topology-specific durable state types and no more than
   three operator recovery steps beyond static.

Across the eight held-out cases, a dynamic mechanism is retained only if it
wins at least three cases and the wins span at least two distinct preregistered
geometry clusters. A tie or one-dimensional improvement with a threshold breach
is a static-workflow win.

## Geometry clusters (assigned before results)

- `G1`: low volume / high coupling / high shared context;
- `G2`: moderate volume / high specialist diversity / high verification burden;
- `G3`: high decomposability / moderate coupling / deadline pressure;
- `G4`: ambiguous or insufficient authority/evidence, where do-not-instantiate
  should win.

Cluster assignment and geometry values are sealed with corpus hashes before
implementation sees held-out content.

## Baseline behavior

- Static baseline uses explicit ordered steps, canonical checkpoints, targeted
  activity retry, independent evaluation and reconciliation before any uncertain
  effect.
- WMI baseline preserves its fixed specialist roster and existing sequencing;
  the experimental harness may adapt only its I/O to canonical contracts and
  must not silently add durability that the baseline does not own.
- Dynamic candidates may change topology, not mission, authority, evidence,
  provider eligibility or resource envelope.

## Analysis and preservation

All runs—including setup failures, negative controls, losers, wrong topology
predictions and killed candidates—produce immutable records. UNKNOWN never
becomes PASS. No threshold is tuned after viewing held-out results. Aggregate
scores cannot hide a hard-invariant failure.

## Decision rule

- Different phenotypes win different geometry clusters: retain the compiler
  thesis and only the winning mechanisms.
- One phenotype wins almost universally: simplify around it.
- Dynamic ties while adding complexity: regress to static.
- Static wins: retain static; the experiment is still successful.
- No new capability: kill the organizational layer and preserve evidence.
