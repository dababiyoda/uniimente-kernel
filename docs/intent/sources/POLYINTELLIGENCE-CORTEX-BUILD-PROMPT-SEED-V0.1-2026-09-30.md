Your refinement sets the governing rule: **eligibility first; optimization second**. Here is the build prompt based on the revised architecture.

---

Build **GREG Polyintelligence Architecture — Seed Experiment v0.1**.

The destination is one governed GREG capable of selecting, composing, evaluating, and eventually developing different computational competencies. This branch must establish a small executable proof of heterogeneous cognition while preserving that destination.

1. **Inspect the repository and integrate with existing ownership.**

   Read repository instructions, constitutional policies, Capability Genome, capability routing, model routing, causal memory, receipts, Kernel authority, and the Consequence Gate before editing. Verify current implementations and project status rather than treating historical descriptions or PR references as current facts.

   Implement `IntelligenceGenome` as an extension or cognitive projection of the existing Capability Genome. Reuse its identifiers, versioning, persistence, lifecycle, and eligibility machinery.

   Keep VEPMC 0→1 as the operational priority. Preserve startup, persistence, mission execution, and Chromebook requirements. Report repository verification separately from Chromebook verification, founder use, and reboot verification.

2. **Preserve the five architectural layers.**

   Represent these classifications in contracts and documentation:

   - Primitive / basal intelligence.
   - Distributed / collective intelligence.
   - Solver / macro-cognitive intelligence.
   - Developmental / morphogenetic intelligence.
   - Meta-intelligence / Polyintelligence Cortex.

   These are selectable scales and mechanisms. They do not require five services or sequential execution.

   Any biological concept used in the implementation must identify its mechanism, state variables, interface, feedback loop, measurable behavior, test, and failure condition.

3. **Enforce hard gates before ranking.**

   Evaluate applicable law, rights, founder-authorized scope, consent where required, evidence sufficiency, unacceptable harm, budgets, and consequence boundaries before ranking consequential options.

   A favorable advantage score cannot override a failed gate. Materially unresolved gates must produce an explicit unresolved state, bounded evidence acquisition, authorized adjudication, or abstention.

   Use existing policy and authorization records. Model-generated interpretations, proof artifacts, confidence, reputation, and benchmark results cannot create permission.

   Among eligible options, seek the strongest verified, durable lawful advantage under the applicable founder policy. Preserve explicit tradeoffs when options are incomparable. Keep uncertainty margins proportional to irreversibility and consequence.

4. **Implement the shared cognitive contracts.**

   Use repository conventions and include, at minimum:

   - `ProblemGeometry`: epistemic class, objective, ambiguity, exactness, uncertainty, causal structure, constraints, sequential or static character, evidence quality, resource limits, consequence vector, reversibility, and unresolved fields.
   - `IntelligenceGenome` cognitive profile: supported geometries, input/output contracts, proof classes, observations, state, memory scope, update rules, recruitment/inhibition behavior, evidence requirements, costs, latency, cognitive light cone, existing authority reference, contraindications, abstention conditions, failure modes, lineage, and benchmark history.
   - Typed proof artifacts appropriate to each implemented route.
   - `CognitiveReceipt`: inputs and evidence references, versions, geometry, eligibility results, route rationale, alternatives, assumptions, output, uncertainty, proof artifact, verifier findings, shared dependencies, expenditure, disposition, and later outcome linkage.
   - Routing-memory records: verified outcome provenance, geometry, attribution uncertainty, competence update, policy version, and rollback reference.

   Receipts must distinguish **formal validity**, **empirical validity**, and **legitimate authority**. Cognitive results create no authority.

5. **Implement the bounded seed repertoire.**

   Activate three solver organs:

   - **Semantic:** use the existing model integration for interpretation, synthesis, hypotheses, and explanation. Return source-supported claims, assumptions, contradictions, and uncertainty.
   - **Fermi / Estimation:** execute explicit decompositions with units, ranges, dimensional checks, sensitivity, dominant uncertainties, and reference-class anchors where available. Preserve dependencies between uncertain inputs.
   - **Formal:** execute an actual formal solver against an inspectable model. Return assumptions, constraints, solver/version information, status, and available certificates, counterexamples, or unsatisfiable cores.

   Add a first-class **Evidence/Causal route** and an independent adversarial verifier.

   Represent future intelligence families through compatible profiles or extension points. Keep swarm, evolutionary, active-inference, developmental, and MICA/CDPE execution outside this seed experiment.

6. **Give empirical and causal questions a legitimate route.**

   Distinguish factual support, association, prediction, and intervention claims.

   The Evidence/Causal route must identify available evidence, provenance, freshness, contradictions, missing observations, and the question that remains unresolved.

   A causal estimate requires an explicit estimand, identification assumptions, suitable data, confounder treatment, method, and limitations. Where these conditions are absent, return an evidence assessment and propose authorized acquisition, a bounded experiment, domain/human adjudication, or abstention.

   Generated explanations or causal diagrams do not establish causal identification. Passing refutation checks does not prove causal truth.

7. **Build consequence-aware routing and verification.**

   Implement:

   `problem → geometry → cognitive eligibility → budget → route or bounded composition → typed artifact → adversarial verification → abstain/recommend/handoff → receipt`

   Begin with a deterministic, inspectable routing policy. Semantic models may propose geometry features, but their proposals require validation and retain uncertainty.

   High consequence does not automatically select Formal. Formal methods decide formalizable properties; empirical correspondence and authority require separate checks.

   For formalization, preserve:

   `original requirement → structured model → reverse translation → discrepancy check → counterexample search → solver result`

   Reverse translation helps detect errors; it does not establish completeness. Emit explicit states for incomplete formalization, unverified real-world premises, unavailable dependencies, timeouts, and inconclusive results.

   The adversarial verifier must inspect evidence and artifacts and attack assumptions, omitted constraints, contradictions, and boundary violations. Record correlated dependencies; agreement between model prompts alone does not establish independent verification.

8. **Preserve the consequence boundary.**

   Cortex outputs are recommendations, abstentions, bounded tests, or handoffs. External consequences continue through the existing Kernel authority and Consequence Gate.

   Evaluate harm separately across physical, financial, rights, privacy, reputational, discrimination, third-party, irreversible disclosure, systemic, and tail-risk dimensions. Missing measurements remain unknown.

   When relevant, distinguish immediate victim protection, containment, evidence preservation, safe contact, escalation, restitution, and recurrence prevention. Preserve evidence with appropriate access and disclosure controls.

9. **Freeze meaningful evaluation before measuring gain.**

   Create smoke coverage for semantic synthesis, Fermi estimation, formal constraint feasibility, and an unresolved causal intervention question. Then establish a larger held-out suite containing mixed, adversarial, malformed, and unanswerable cases.

   Freeze cases, scoring, configurations, budgets, partitions, and exit thresholds before the reported evaluation. Development examples must remain separate.

   Compare against:

   - A strong configured always-LLM baseline.
   - An ordinary model committee baseline.
   - The routed seed.

   Use equivalent available facts and disclose resource differences. Include classification, verification, and orchestration overhead.

   Report decision quality, critical errors, unsupported certainty, abstention quality, calibration where measurable, gate violations, cost, latency, sample counts, and uncertainty separately. Correct abstention must receive credit.

   Include failures involving stale evidence, contradictory sources, shared misconceptions, omitted constraints, solver outages, exhausted budgets, delayed outcomes, evaluator gaming, and distribution shift.

   Three successful examples establish smoke-test functionality. Claim routing gain only when the frozen evaluation supports it against the declared baselines.

10. **Make learning conditional on verified outcomes.**

    Link problem, geometry, selected methods, recommendation, authorization where applicable, consequence, observed outcome, and attribution.

    Distinguish verified success, observed failure, unresolved outcomes, and absent feedback. A prediction or self-assessment cannot settle competence.

    Attribute contributions cautiously: hypothesis generation, flaw detection, calibration improvement, consumed resources, and failed assumptions may belong to different methods.

    Scope competence to **method × geometry × conditions × version**. Bound updates, preserve rollback, and require sufficient outcome evidence before changing defaults.

    Learning cannot modify permissions, consequence ceilings, evaluators, or constitutional authority. Disabled families remain disabled.

11. **Complete the reviewable experiment.**

    Deliver the implementation diff, contract examples, representative receipts, appropriate tests, reproducible benchmark instructions, measured results, limitations, and evidence for the next expansion.

    Use minimal dependencies and focused integration changes. Implemented families must execute real mechanisms; unavailable mechanisms must return explicit bounded failure or abstention.

    The exit condition is **verified cross-geometry routing gain**, counting quality, cost, latency, error, and truthful abstention, with preserved authority. If gain is absent or inconclusive, report that result and keep the experiment unpromoted.

    Preserve the backcast from Seed to Cortex, Composer, Developmental Cortex, Polyintelligent GREG, and frontier capability discovery. Each advancement requires its own evidence.

**Governing invariant: maximize verified, durable, lawful, founder-authorized advantage after hard gates; compound capability from reality; preserve constitutional authority.**
