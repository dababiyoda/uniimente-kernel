# Worker-independent acceptance (R1-A): results (2026-10-22)

**What GREG can do now that it could not before:** a commissioned worker can no longer close a mission by writing a
test that proves nothing (it must fail on GREG's copy of the base), or by recording an answer its own test agrees
with when the mission bound a different answer or a reviewed verifier refutes it. On the baseline, H3 (vacuous test)
and H4 (coherent lie) reached ACCEPTED, ACHIEVED and a separate-process VERIFIED in both regimes; on the new tree none
of the four pre-registered hostile classes does.

Founder lineage: #190, `INTENT-20261019-UPWARD-ASCENT` (2026-10-19), first capability dividend. Pre-registration:
[`PREREGISTRATION.md`](PREREGISTRATION.md), committed at **`57b5c17`** before any implementation of layers 2-4.

**Floor 4 failed, and could not have passed with this design.** The baseline's appraisal of the honest one_machine
order takes about 0.43 s, most of it one pytest process; the discrimination run is a second pytest process over the
changed test files (about 0.5 s, most of it interpreter and pytest start-up). A +10% budget is about 0.04 s, less than
any extra process start. The absolute cost is about +0.5 s per appraisal, constant in the size of the acceptance
suite (only the worker's changed tests run on the base), so the relative cost falls as suites grow; that last clause
is inference, not measured here. The pre-registration did not say what a failed floor decides; this README keeps the
layer (it holds H3's unique catch) and records the failure, for the founder's review. Candidate remedy, not built:
start the base run concurrently with the acceptance run (wall time about max instead of sum on a multi-core host),
which needs a non-blocking variant of the supervised runner rather than threads with `preexec_fn`.

## Ablation verdicts against the decision rule

- L1 freeze: unique catch H1 (the edited named test still fails on the base, so discrimination does not see it). H2,
  expected unique to the freeze, is also caught by discrimination, because the worker's `tests/conftest.py` travels to
  the base run with its other test-side files and flips the base failure to a pass. Kept.
- L2 discrimination: unique catch H3. Kept (floor 4 cost recorded above).
- L3 bound artifact: unique catch H4b (optimal but uncertified plan). Kept.
- L4 re-derivation: unique catch H4v (lie on an order with a verifier and no bound value). Kept.
- H4 is caught by L3 and L4 together (neither alone is necessary); its finding names both the bound value and the
  verifier, as the threshold requires.

## Integration trace (one_machine path)

1. The founder signs the one_machine mission; `cognition.solve` answers with a problem-level certificate and
   `answered` passes.
2. The commission strategy's `bind` renders that receipt's result into the order's `context` as
   `CERTIFIED_PLAN_JSON:\n{...}`; `WorkOrder.from_params` validates `bound_artifacts`/`verifiers`
   (`acceptance_bindings`); the order digest freezes them with the context.
3. The worker edits a private clone; GREG collects the patch, runs acceptance with no network and commits on
   `greg/<order>`; the receipt binds the order digest.
4. `worker.appraise` (in-body sensor): fresh clone at the recorded base, retained patch applied, scope and freeze
   checks; then `delivered_inputs` reads, before any worker code runs in the clone, the changed test-side files and
   the bound artifact from the index and `problem.json` from the base commit; acceptance runs; `bound_artifact_findings`
   compares `plan/plan.json` with the bound value; `rederivation_findings` runs `assignment.staffing`; if nothing has
   refused, `discrimination_findings` runs the changed tests once on GREG's copy of the base (`base_tree`).
5. Only ACCEPTED closes `work_accepted`; the handoff is written; the mission closes.
6. The separate-process appraiser (`python -m greg.appraisal`) re-runs `worker.appraise` with the same four layers
   over the head-pinned ledger and returns VERIFIED or not.

## Negative results

- **Floor 4 failed** (above): about +0.5 s, +100% or more, per appraisal of a fast honest suite.
- **H3h (post hoc):** a vacuous test whose helper sits on the code side (`plan/check.py`) fails on the base because the
  helper is missing, so discrimination passes it; with a correct plan, L3 and L4 pass too; it is ACCEPTED and VERIFIED
  on both trees. Discrimination is necessary, not sufficient. Recorded as a strict xfail
  (`tests/integration/test_greg_acceptance_dividend.py`), which turns red the day something refuses it.
- Discrimination judges the worker's changed test files as one run: a vacuous file alongside a discriminating one is
  not refused.
- L3/L4 apply only where an order binds a value or names a reviewed verifier; a plain code_change order gets L1+L2.
  One verifier exists (`assignment.staffing`), and it refuses problems with more than 16 orders rather than assume
  optimality.
- The pre-registration expected L1 to catch H2 uniquely; it does not (above).
- The supervised regime refuses the envelope only inside the evaluated process; the separate-process appraiser of an
  honest supervised closure ran with this host's envelope.
- Workers are scripted doubles of the declared classes, not an adaptive adversary.

## Next unclosed parent requirement

Test strength beyond discrimination (H3h): a check that the worker's tests fail on a mutated delivered artifact, or
on the bound value's negation, so a test that cannot tell right from wrong is refused, within a cost the founder
accepts (floor 4 already shows one extra process costs about 0.5 s). After that, #190's second dividend: graduated
worker confinement with #173's Landlock grants as the floor under `supervised`.
