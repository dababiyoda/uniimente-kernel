# UNIIMENTE Foundry

> **Founder-effect rule (INTENT-0030):** Foundry work begins from the desired transformation, not from a favored metaphor, repository, technology catalog, or existing subsystem. Preserve the founder's target effect, search reality, extract causal mechanisms, and build only what remains missing. See `docs/FOUNDER_EFFECT_COMPILER.md`.

The package contains bounded institutional foundries with different jobs. These are tools inside UNIIMENTE's broader Capability Genesis process; they do not define the complete process.

## 1. Evidence-Governed Media Foundry

Build ratifiable synthetic media companies around evidence-governed Territory Graphs, owned relationships, useful actions, products, correction duties, and Gate-only publishing.

## 2. Asymmetric Advantage Foundry

Convert a Phase Zero qualified opportunity into:

1. eleven preserved strategy routes;
2. a selected Advantage Architecture;
3. an eight-sided tribunal report covering four control super-nodes;
4. a dependency-aware, non-executing Composition Plan using the registered technology/capability arsenal;
5. an OMNIMORPH Organ Manifest and simulation **only when temporary organ composition is justified**;
6. an activation request that still requires human ratification and the canonical Consequence Gate;
7. a sealed Advantage Genome only after a clean paid, accepted, externally verified, reconciled outcome.

A Composition Plan is not a Genome. An Organ Manifest is not activation. A Gate receipt is not customer success. A payment without accepted external outcome is false closure.

## Relationship to Mechanism Recombination and Capability Genesis

The repository's current Foundry implementation is **not** a license to force every problem through the 55-technology catalog or OMNIMORPH.

For a CapabilityDeficit, the broader search space is:

```text
existing UNIIMENTE capability
-> reconfiguration / composition
-> commodity software
-> open-source repository/library
-> API / plugin / connector / model / service
-> authorized computer use
-> small generated utility/adapter
-> coding agent or temporary specialist team
-> mechanism extraction / mutation / recombination
-> new architecture if the residual deficit still requires it
```

A repository such as Build-Your-Own-X is a **mechanism anatomy atlas**, not a product backlog. Extract primitives and causal invariants; discard branding and source-product assumptions; mutate/recombine only when that creates a capability the simpler routes cannot provide.

Likewise, biological metaphors are mechanism mines. A useful mechanism may be retained; the source-domain surface form is disposable.

The strongest route may be boring. A mature external tool that closes the target effect can correctly beat an elegant internally invented subsystem.

## Buildability contract

- **Existing mechanism:** Phase Zero adapters, Territory Graph, technology/capability registry, Capability Genome Registry, hash-bound Ratifier, Spider-Web Tribunal, Consequence Gate, Evidence Ledger, Business Foundry, and Whole-Body Closure Controller.
- **Defined interface:** `TerritoryGraph`, `MediaCompanyCharter`, `CompanyFoundry`, `DistributionLoop`, `opportunity_from_canonical`, `AdvantageFoundry`, `SpiderWebTribunal`, `FoundryComposer`, and `FoundryPipeline`.
- **Bounded authority:** agents draft and rank; humans ratify; every external effect crosses the Gate; metrics, model consensus, tribunal output, plans, manifests, and newly created capabilities never create authority.
- **Available dependencies:** canonical Kernel contracts, policy, identity, provenance, Capability Genomes, registered technology status, Business Foundry receipts, approved platform adapters, and externally sourced mechanisms whose provenance/licensing is recorded.
- **Security model:** synthetic disclosure; no purchased metrics, outrage optimization, vulnerable-attention exploitation, fear-based retention, self-ratification, raw-model intake, changed-content replay, target-architecture activation, arbitrary receipt substitution, hidden external incidents, or authority inheritance by generated/acquired code.
- **Failure modes:** invalid graph, weak or stale evidence, retired node, unratified or edited charter, incomplete governing transaction, fewer than eleven routes, missing tribunal lens or super-node, dependency conflict, partial/target technology, failed simulation, expired ratification, mismatched Gate receipt, dirty external outcome, duplicate Genome version, literalized-metaphor architecture, or new subsystem created without checking simpler real mechanisms.
- **Acceptance tests:** rooted DAG and one owned exit; full route tournament; eight tribunal lenses; four super-nodes; dependency and detachment order; plan identity; capability and budget envelopes; human ratification; exact Gate receipt; false-closure detection; clean external sealing; correction, retirement, restart recovery, and effect-vs-metaphor trace where applicable.
- **Recovery path:** suspend or reject the affected stage, preserve negative evidence, return to the nearest verified state, reconfigure the mechanism/architecture/plan, adopt a simpler route when it wins, publish a new immutable version, reratify changed artifacts, reconcile obligations, and resume only through the Gate.
- **Resource ceiling:** Opportunity budget, Composition Plan budget, Capability Genome envelopes, OMNIMORPH aggregate budget, evidence experiment budget, publication budget, evidence floor, graph-size bounds, and founder-attention ceiling.
- **Operating cost:** research, validation, compute, external tools/services, capability composition, evidence verification, content production, correction, platform APIs, customer delivery, reconciliation, compliance, and founder time.
- **Legal operator:** a named human or lawful entity, never UNIIMENTE, Foundry, OMNIMORPH, an agent swarm, or a synthetic persona.
- **Handoff:** qualified OpportunitySpec, complete route archive, immutable architecture hash, tribunal report, mechanism provenance, Composition Plan when used, Organ Manifest when used, simulation report, ratification record, Gate receipt, commercial closure receipts, and sealed or rejected Genome decision.
- **Replaceable:** models, strategy generators, renderers, runtimes, platform adapters, storage, external mechanism providers, and individual capability implementations may change behind stable contracts; the Constitution, evidence boundary, and external authority path may not be bypassed.

## Anti-waste invariant

> **Do not build because the metaphor sounds advanced. Build because the mechanism measurably closes the founder's effect better than the alternatives.**
