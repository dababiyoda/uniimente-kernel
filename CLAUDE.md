## Founder-effect interpretation — mandatory

**Preserve the effect. Do not literalize the metaphor.**

Alfonso frequently expresses target capabilities through biological, institutional, mythic, or science-fiction metaphors: egregore, organism, morphogenesis, cells, tissues, organs, immune system, metabolism, healing, regeneration, nervous system, embodiment, omniscience, Jarvis, immortality, and related language.

Unless Alfonso explicitly requires the implementation itself to be literal, treat these as **outcome specifications and mechanism-discovery prompts**. Translate them into observable effects, then search for the simplest lawful, technically real mechanism that can produce those effects.

Before inventing architecture, check: existing UNIIMENTE capabilities -> composition/reconfiguration -> mature commodity infrastructure -> open source -> APIs/plugins/services -> authorized computer use -> small bounded utility -> coding agent/team -> OMNIMORPH if organization design is actually needed -> genuinely new architecture.

Do not silently shrink a science-fiction aspiration because current technology cannot realize its surface wording. Preserve the destination, identify the underlying effect, label the current capability gap honestly, and build the strongest real approximation or enabling mechanism.

**Canonical morphogenesis:** functional capability formation/reconfiguration in response to a verified discrepancy or CapabilityDeficit. It does not require digital cells, tissues, developmental fields, decentralized topology, or organizational self-assembly. Those are optional research mechanisms that must beat simpler baselines.

Historical literal-morphogenesis work is preserved as research, mechanisms, tests, counterevidence, and lineage. Its literal framing is not binding.

## Permanent rules

- Preserve every useful implementation, test, document, branch and proof record.
- Never destroy institutional memory to simplify architecture.
- Establish one canonical authority path while retaining multiple governed capability implementations.
- Connect disconnected systems through typed contracts, adapters, events,
  registries and capability composition.
- **Search for, acquire, adapt, or compose an existing mechanism before building missing technology. Build only the residual capability that remains missing.**
- Prefer mature commodity infrastructure and build UNIIMENTE's proprietary control,
  proof, memory, composition and evolution layers above it.
- Treat open-source projects and existing tools as mechanism sources and usable capabilities, not as things that must be recreated from scratch.
- Do not claim completion without executable evidence.
- Do not claim an effect because an internal simulation resembles the founder's metaphor.
- Continue until all unblocked work is implemented, tested, attacked, verified,
  documented, committed and handed off.
- Alfonso retains ultimate lawful authority.
- Intelligence never creates authority.
- No component may authorize its own promotion or expand its own sovereignty.
- Building software does not authorize installation; installation does not authorize activation; activation does not grant consequence authority.
